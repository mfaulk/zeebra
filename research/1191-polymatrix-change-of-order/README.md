# #1191: change of order through a polynomial matrix

The data behind [`docs/research/polymatrix-change-of-order.md`](../../docs/research/polymatrix-change-of-order.md).
No timing is taken here. The census counts are deterministic; the stage medians the model uses are
#1039's committed publication read (`../1039-wiedemann-lex/tables.md`, `5cce19f0`).

| File | What it is |
|---|---|
| `probe.py` | One `examples/lex_pipeline` process per (row, arm), pinned to one CPU. Development mode |
| `census.jsonl` | `--arm probe` records: the `module_census` of each row's grevlex staircase and the last operator's shape |
| `model.py` | `tables.md` from `census.jsonl` and #1039's stage medians: census, operation counts, and the row-level gate |
| `tables.md` | Generated by `model.py` |

```sh
cargo build --release --example lex_pipeline
python3 research/1191-polymatrix-change-of-order/probe.py --pipeline target/release/examples/lex_pipeline \
  --rows wd-4-6,wd-4-10,wd-3-30,wdsq-4-10,wd-6-6,cyclic-7,katsura-10,katsura-11,katsura-12,pquad-10-1,pquad-12-1 \
  --arms probe --out research/1191-polymatrix-change-of-order/census.jsonl
python3 research/1191-polymatrix-change-of-order/model.py > research/1191-polymatrix-change-of-order/tables.md
```

`probe.py` appends, so remove `census.jsonl` before regenerating it. Probe records carry no clocks,
so a regenerated file is identical.

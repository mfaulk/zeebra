## One harness, one protocol (#958)

Every Zeebra arm, F3 and M31 alike, runs the same `examples/sig_f4_study.rs`:
[`research/m32-katsura9-gap/harness.rs`](../m32-katsura9-gap/harness.rs) (SHA-256 `9d2b2776…`),
copied over each tree's own example before building. The library is therefore the only thing that
differs between the `f3` and `m31` binaries. Within a suite every arm uses the same protocol:

| Suite | Protocol | Rows |
|---|---|---|
| `dev`, `held` | one solve per fresh process; process wall. No `--calls`, no `--repeat` | every row of ≥ 50 ms |
| `small` | `--calls 20` on every arm: one cold call, 20 warm with the first basis kept live; the median warm call per process (#934) | katsura-4 (both fields), katsura-9 |
| `certify` | one child per row, `--certify` after the timed solve | every dev and held-out row |

`--repeat` is not used anywhere: on katsura-9 it costs 5–6% through glibc heap trimming (#958).

## Comparand bases

`tables.md` §8 compares each comparand's basis *text* with Zeebra's digest. grobx's text matches
exactly. groebner-rs writes terms with spaces (`x1 + x2`), so its raw text never matches and the
column reads "text differs"; with spaces removed and the polynomials sorted, every groebner-rs
basis in the `wide` and `rs` archives equals Zeebra's digest on all four rows. MQ10 answers are
verified by the comparand-scaling controller against #739's references.

The controllers' own archives (`wide-*-pass*.json.gz`, `rs-*-pass*.json.gz`, `mq10-try*.json.gz`)
hold full inputs and bases and stay outside the repository; the extracts name each by SHA-256.

## Arms

`f4:W` F3 conventional F4; `en:W` F3 adaptive path (`f4_signature`, #950's dispatch); `sg:W` F3
signature engine forced (`--claim` above one worker); `mf4:16`, `men:W`, `msg:16` the same three at
the M31 reference; `ec:16` the adaptive path with certification. Arms are interleaved and rotated
one place per repetition, with a 1 s settle before each child; children are `taskset` from CPU 8,
`rss-guard` at 8 GiB, 180 s solve cap (600 s more for certification).

## Reproduce

```sh
B=/buildcache/cargo-target/zeebra-942          # never under $HOME or /tmp
export RUSTC_WRAPPER="" CARGO_INCREMENTAL=0 TMPDIR=$B/tmp
for c in f3:9c24a24f m31:8715c8ed; do
  mkdir -p $B/src/${c%%:*} && git archive ${c#*:} | tar -x -C $B/src/${c%%:*}
  cp research/m32-katsura9-gap/harness.rs $B/src/${c%%:*}/examples/sig_f4_study.rs
  (cd $B/src/${c%%:*} && CARGO_TARGET_DIR=$B/target-${c%%:*} \
     cargo build -j24 --release --locked --features research-sigf4 --example sig_f4_study)
  mkdir -p $B/bin/${c%%:*} && cp $B/target-${c%%:*}/release/examples/sig_f4_study $B/bin/${c%%:*}/
done
(cd $B/src/f3 && CARGO_TARGET_DIR=$B/target-f3 cargo build -j24 --release --locked --features research-sigf4 \
   --example zeebra_driver --example wide_corpus \
 && CARGO_TARGET_DIR=$B/target-f3 cargo build -j24 --locked --features external-runners --example competitive_sweep)
mkdir -p $B/target-f3/bin && cp $B/target-f3/release/examples/{zeebra_driver,wide_corpus} $B/target-f3/bin/
cp /path/to/{grobx-driver,groebner-rs-driver} $B/target-f3/bin/   # M30-0's builds; SHA-256 in binaries.sha256
setsid -w research/m32-final/run.sh OUT dev small held certify
setsid -w research/m32-final/run.sh OUT rs wide mq10 certified   # run.sh defaults ZEEBRA_MACHINE=5995wx
for s in dev small held certify certified; do gzip -n -c OUT/$s.jsonl > research/m32-final/$s.jsonl.gz; done
python3 research/m30-final/extract.py OUT research/m32-final
python3 research/m32-final/summarize.py --extract-rs OUT research/m32-final
python3 research/m32-final/summarize.py research/m32-final > research/m32-final/tables.md
```

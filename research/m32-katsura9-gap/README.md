# #958: the katsura-9 signature-F4 gap is the harness, not the library (and #964)

**Measured at:** libraries `8715c8ed` (M31), `c1d93389` (`ce67df76`'s `src/`), `588d2a44` (Gate R
revision 1) and `f427e8d7` (F2), each built with one shared harness, [`harness.rs`](harness.rs)
(SHA-256 `9d2b2776…`), plus `c1d93389`'s and `f427e8d7`'s own `examples/sig_f4_study.rs`; #964's
re-read at `45107ec3` (tag `measured/939-instrument`). Records and scripts at tag
`measured/958-katsura9-gap`. 2026-11-20, `tools/bench-reserve.sh` on CCDs 1–2 (CPUs 8–23) under
`benchlock` (`zb-958`, `zb-964`); no other benchlock window overlapped ([`benchlock.log`](benchlock.log)).
Load at child start 0.7–6.1 (median 2.1), no compiler processes in any `cpu-context` snapshot.
rustc 1.99.1. Executable SHA-256s: [`binaries.sha256`](binaries.sha256).
**Tables:** [`tables.md`](tables.md), generated by [`summarize.py`](summarize.py) from the records.

## Verdict

**The ~2.5% F2 ÷ M31 gap on katsura-9 / 2⁶⁴−353 is a protocol confound, not library code.** Run
under one harness and one protocol (`--calls 20`), F2's library is level with or faster than M31's,
and `--repeat 21` alone, on the same binary, costs 5–6% through glibc returning the heap to the
kernel between calls.

| Ratio (median warm call per process, paired, n = 21) | 1 worker | 16 workers |
|---|---|---|
| F2 ÷ true M31 `8715c8ed`, one harness | 0.997 [0.984, 1.001] | 0.985 [0.983, 0.986] |
| F2 ÷ `ce67df76` (Gate R/Q's reference library) | 1.001 [0.997, 1.006] | 0.990 [0.989, 0.991] |
| Gate R rev 1 ÷ `ce67df76` (Gate R read 1.006 / 0.989) | 0.998 [0.990, 1.001] | 0.988 [0.986, 0.990] |
| F2 ÷ rev 1 (same measured `src/`, A/A) | 1.002 [1.000, 1.009] | 1.002 [0.997, 1.004] |
| `ce67df76` ÷ `8715c8ed` (#947/#948's refactor) | 0.998 [0.989, 1.011] | 0.996 [0.994, 0.997] |
| **`--repeat 21` ÷ `--calls 20`, the same F2 binary** | **1.054 [1.051, 1.060]** | **1.058 [1.054, 1.063]** |
| `c1d93389`'s own example ÷ the shared harness (text placement) | 0.997 [0.991, 1.001] | 0.997 [0.996, 0.999] |
| F2's own example ÷ the shared harness, both `--repeat 21` | 1.001 [0.995, 1.006] | 0.999 [0.996, 1.003] |
| #941's pairing: F2 own `--repeat 21` ÷ `c1d93389` own `--calls 20` | 1.060 [1.055, 1.067] | 1.050 [1.044, 1.054] |

So, against #958's suspects:

1. **Harness (suspect 1): confirmed.** The protocol alone moves katsura-9 by 5–6%, and #941's
   cross-protocol pairing reproduces as a "regression" of the same size, while every one-protocol
   library ratio is ≤ 1.002. This session reads the cross-protocol pairing at 1.050–1.060, larger
   than #941's 1.024–1.029; the direction and cause agree, the size difference is not explained here.
2. **Code placement under fat LTO (suspect 2): not needed, and small.** Swapping harness text around
   one library moves it 0.997–1.001. Per the brief it was not re-checked further.
3. **#947/#948's refactor (suspect 3): no cost.** `ce67df76` ÷ `8715c8ed` is 0.998 / 0.996. This is
   the first warm-call timing of the true M31 `8715c8ed`.
4. **#950's dispatch (suspect 4):** F2 ÷ rev 1 is 1.002, as expected from identical measured code.

**Mechanism (diagnostic `alloc` suite, n = 11).** `--calls` keeps the first call's basis alive while
the warm calls run; `--repeat` retains nothing, so each call frees everything and glibc trims the
heap top back to the kernel, and the next call faults it in again. With trimming disabled
(`GLIBC_TUNABLES=glibc.malloc.trim_threshold=1073741824:glibc.malloc.top_pad=1073741824`) the same
`--repeat 21` run drops 8–9% (0.922 / 0.911) and lands at 0.973 / 0.967 of `--calls 20`. The penalty
is uniform across the call sequence, not a warm-up effect (per-position medians in the records).

**For the gates (not changed here).** Gate Q's T4 katsura-9 cell (head `--repeat 21` ÷ `c1d93389`
`--calls 20`, 1.036) carries this confound against the head. Its recorded verdict stands; re-reading
it under one protocol is #941's or the owner's call, and #942 can cite this. Gate R's `small` suite
used `--calls` on both arms and is not affected. Any future warm-call A/B should run both arms
through one harness and one flag, and `--repeat` is allocator-sensitive on rows this small.

## Method

- **Builds.** `git archive` of each commit into its own tree and `CARGO_TARGET_DIR` under
  `/buildcache/cargo-target/zeebra-958`, `RUSTC_WRAPPER=""`, `cargo build --release --features
  research-sigf4 --example sig_f4_study` (fat LTO, one codegen unit, x86-64-v3 from each tree's own
  `.cargo/config.toml`; `Cargo.lock` and the release profile are identical across the four). In the
  `h-*` trees `examples/sig_f4_study.rs` was replaced by `harness.rs`: `c1d93389`'s example (which
  `c1d93389` itself, `588d2a44` with six fewer summary fields, and Gate R ran) with `f427e8d7`'s
  `--repeat k` backported (k − 1 calls each dropped inside its clock, then the reported call, all in
  `calls_ns`). It compiles unchanged against all four libraries (on `8715c8ed` with one
  `unexpected_cfgs` warning for the absent `research-sigf4-usage` feature, whose block is cfg'd out).
- **Metric.** Per process, the median warm call: `warm_ns` under `--calls 20`, `calls_ns[1:]` under
  `--repeat 21`, as Gate Q's `summarize.py` reads them. Paired by repetition; median ratio with a 95%
  percentile bootstrap (20,000 draws).
- **Session.** [`campaign.py`](campaign.py) on M31's child runner (`research/m31-baseline/campaign.py`
  `run_one`: CCD-aligned `taskset` from CPU 8, `cpu-context` before and after each child, frequency
  sampling, `timeout --signal=INT`, `rss-guard` at 8 GiB on the child's own comm). One block per
  worker count, seven arms rotated one place per repetition, 1 s settle before each child (#827's
  boost hysteresis). 294 + 66 children, all complete, one basis SHA-256.

## Reproduce

```sh
B=/buildcache/cargo-target/zeebra-958     # never under $HOME or /tmp
for c in 8715c8ed c1d93389 588d2a44 f427e8d7 45107ec3; do git archive -o $B/$c.tar $c; done
# extract into $B/src/{h-8715c8ed,h-c1d93389,h-588d2a44,h-f427e8d7,own-c1d93389,own-f427e8d7,
#   m32-45107ec3,split-45107ec3}; copy research/m32-katsura9-gap/harness.rs over
#   examples/sig_f4_study.rs in each h-* tree; in each tree:
#   RUSTC_WRAPPER="" TMPDIR=$B/tmp CARGO_TARGET_DIR=$B/t-<tree> cargo build --release \
#     --features research-sigf4 --example sig_f4_study      # research-sigf4-split for split-45107ec3
# copy each binary to $B/bins/<tree>/; $B/bins-ab/{m32,split} -> ../bins/{m32,split}-45107ec3
setsid -w research/m32-katsura9-gap/run.sh OUT gap ab
setsid -w research/m32-katsura9-gap/run.sh OUT alloc
for s in gap alloc ab; do gzip -n -c OUT/$s.jsonl > research/m32-katsura9-gap/$s.jsonl.gz; done
python3 research/m32-katsura9-gap/summarize.py research/m32-katsura9-gap > research/m32-katsura9-gap/tables.md
```

`alloc` was added after `gap` and `ab` had run and ran in its own reservation; `run.sh` and
`campaign.py` as committed are the versions that ran it, and the `gap` arms and commands are
unchanged from the version that ran `gap`.
